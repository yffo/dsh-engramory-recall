# dsh-engramory-recall

给 [Engramory](https://github.com/tinqiao-oss/engramory) 的 markdown 记忆库加四件事：

1. **本地自动召回** —— 模型不用自觉去读索引，该想起的自己会浮现；
2. **写入治理** —— fail-closed 校验闸门 + 落盘审计 + 静态体检；
3. **自动归档** —— 把追加式的「第 N 批」章节整段搬进 `<笔记>-history.md`，主文件只留结论与现状；
4. **可观测性** —— GUI 里一个「记忆」标签页，看得到库里有什么、这轮召回了什么、写得干不干净。

全部用 `node:` 内置模块实现：零第三方依赖、零网络、零模型调用、零常驻进程。

## 它怎么守住底线

| 底线 | 本插件如何守 |
|---|---|
| 数据不出本机 | 纯 `node:` 内置模块；`capabilities` 只需要 `fs-read` / `fs-write`，**不需要 network** |
| 不每轮塞正文 | 只在**命中**时注入，且只注入「文件名 + 一行片段」；没命中一个 token 都不注入 |
| 纯文本、可跨 Agent | 只读记忆库的 markdown，不建库、不产生索引文件 |
| 有上限 | 注入量硬上限 `maxChars`（默认 480 字符）+ `maxPointers`（默认 4 条）+ 预算降级阶梯 |
| 不静默改数据 | 召回**只读**、体检只**报告**、归档每次都要显式确认且先备份、写入闸门只**拒绝**不代写 |

## 为什么是它：跟市面上的记忆插件正面比

不是因为功能更多。是因为**三条否决线**先把绝大多数方案卡掉了 —— 这三条不是推演出来的，
是两次真实卸载换来的（云端 Memmy 装了两遍、卸了两遍）。

| 否决线 | 判据 | 倒在这条线上的 |
|---|---|---|
| **数据不出本机** | 正文、embedding、摘要，一个字节都不该离开这台机器 | Memmy（`api.memmy.cn`）、Hindsight（默认上云）、DSH-SEP（抽取走 `api.deepseek.com`） |
| **用不上就不计费** | 没命中就该是零 token、零检索，而不是"少花一点" | Memmy（每轮无条件 550–1550 tokens）、DSH-SEP（每步 ~1250 字符 guidance + ≤4200 字符快照）、OpenViking（强制服务端 + 每轮注入） |
| **不做不可逆的事** | 可以不写，不能替人删 | 所有"自动遗忘/自动合并"型方案：删掉的记忆找不回来，而记忆系统的价值恰恰在长尾 |

### 优势具体在哪

1. **召回是"命中才花钱"**：门控不通过（寒暄 / 极短 / 空）**一次检索都不跑**；命中才注入，
   且只注入「文件名 + 一行片段」，硬上限 480 字符。对照组是每轮固定 550–4200 字符的常驻开销。
2. **召回质量是量出来的，不是声称的**：28 条真实查询基线（`recall@4` / `top-1` / 对照组），
   每个机制上线前后都跑一遍；**三条看起来很美、实测零收益的路被写进 README 当场否决**（见文末）。
3. **写入侧有闸门**：记忆系统普遍只管"怎么取"，不管"写进来的干不干净"。这里是 fail-closed ——
   **不能证明合法就不落盘**，而且拒绝之后后续监听器翻不回来。
4. **写入侧还有另一半**：闸门管"写进来的干净"，**没有任何机制管"该写的被写了"**。
   机制 8（沉淀提醒）专门补这个缺口，长任务跑到最后想不起来落盘时提醒一次。
5. **全部可观测**：召回日志（含命中分数、被降权的条目）、笔记列表、体检、**写入审计**
   （每条放行与拒绝都留痕）、索引原文、归档计划 —— 六页签，都是只读路由。
6. **零依赖**：全 `node:` 内置模块。不是洁癖 —— 依赖越少，三年后还能跑的概率越高。

### 有一条我们确实不如 mneme

`dsh-mneme` 敢**自动**归档，是因为它 **SQLite 才是真相源**、markdown 只是可以重建的投影 ——
归档丢的是一份视图。我们的 markdown 就是唯一真相源，照抄它的做法等于替用户删资料。

现在的归档是另一条路：**不截断、不丢原文**，把追加式章节**整段搬到同目录的 `<笔记>-history.md`**，
搬出去的文件仍在库里、仍被索引、仍能被召回，搬之前先备份到 `.archive-backup/<时间戳>/`，
而且每次执行都要显式确认。代价是主文件变小得比它慢，换来的是**没有一步不可逆**。

## 工作机制

### 召回：发生在每个用户轮的第一个 step

1. 取出这批消息里最后一条**真人**消息，做可检索性门控 —— 空、寒暄（继续 / 嗯 / 好的 / ok…）、
   短于 4 字的消息**直接放行，零开销**；
2. 超长消息**头尾各取一半**（中间通常是粘贴的日志/正文，噪音最多），头部再收敛到前 3 句；
3. BM25 检索 + 同义扩展 + IDF 选词，取前 `maxPointers` 条；
4. 命中 → 追加一条 `role: user` 的插件消息（`source.kind = plugin:dsh-engramory-recall`、
   `form: notice`），内容是「可能相关的既有条目」= 文件名 + 命中行片段 + 一句「需要细节自己 read」；
5. 没命中 → 原样放行。

### 八个机制一览

| # | 机制 | 治什么 |
|---|---|---|
| 1 | 同义扩展（38 条口语→技术词）+ 连字符再切分 | 中文口语与笔记用词对不上的「同义鸿沟」 |
| 2 | 超长正文按 `##` 切桶 + **整篇**长度归一 | 单篇巨文霸榜（一篇 267KB 的笔记曾占掉 1/4 召回位） |
| 3 | 寒暄 / 极短消息门控 | 「继续 / 嗯」这类消息 10/10 注入噪音 |
| 4 | **写入闸门（fail-closed）** | 不合规文件名、缺失 frontmatter、疑似真实凭据 |
| 5 | 注入去重 | 同一批指针上一轮已在上下文里，不重复计费 |
| 6 | 预算降级阶梯 | 装不下的条目塌缩成只剩文件名，而不是静默丢掉 |
| 7 | 跨轮轮换降权 | 最近注入过的条目在后续轮次乘 0.5，把机会让给别的笔记 |
| 8 | 沉淀提醒 | **长会话一次都没写过记忆库时，提醒一次** —— 补「该记的没记」 |

### 写入闸门（`guard.js`）

注册为宿主的 `ctx.tools.guard()` **单调守卫**：模型用 `write` / `edit` 往记忆库里写时先静态复核，
不合规就**拒绝这次工具调用**（拒绝理由直接回给模型），且后续监听器**无法把拒绝翻回允许**。

四类判定：

| 判定 | 规则 |
|---|---|
| 文件名 | 必须匹配 `<user\|feedback\|project\|reference>-<小写slug>.md` |
| frontmatter | 必须有头部块，且含 `name` / `description`，`type` 与文件名前缀一致 |
| 凭据 | 6 类真实密钥（私钥块 / `sk-` / `ghp_` / `AKIA` / `xox` / JWT）+ 键值对形式；**占位写法放行**（`process.env.X`、`<YOUR_TOKEN>`、`CHANGEME`、`***`…） |
| 体积 | 单篇 ≤ 100KB |

`edit` 只能看到片段、看不见结构，所以它只查文件名与凭据（返回 `partial: true`）。
放行与拒绝**都**追加到 `<storePath>/.engramory-audit.jsonl`（JSONL，含 `epoch` 规则版本，
超 512KB 自动轮转）。

**边界（务必知道）**：`guard` 只拦 `write` / `edit` 工具调用 —— `bash` 重定向它看不见。
它是「正路守卫」，不是沙箱；兜底靠体检器定时扫（真实抓到过两篇绕过闸门的裸 markdown）。

### 体检器（`doctor.js`）

纯静态、**只报告不动手**。12 项检查：库不可读、索引指向不存在的文件、孤儿笔记、索引重复、
文件名不合规、`name` / `type` 与文件名不一致、缺 `description`、超 100KB、
待办 30 天没更新、**失联路径**（同一目录名出现在多个位置、其中有的已不存在）、
**归档建议**（超 64KB，**或**「第 N 批」式追加章节超过 20 个）、疑似重复主题。

三条防误报纪律：路径比较前先规范化（`~/x` 与 `/Users/you/x` 同处、尾斜杠不算另一个位置、
含 `...` 的是缩写、一层深的隐藏目录如 `~/.dsh` 是各工具自己的配置位不算冲突）；
缺 `description` 时不参与相似度比较（否则 `undefined` 会变成共同 token 算出假相似）；
判断路径是否还在要用 `statSync` 不抛错，**不能用 `isFile()`**（软链指向目录时它返回 false）。

**它不做语义冲突检测** —— 已实测证伪：对全库笔记两两算词面相似度，最高的一组（0.445）
全是**毫不相干的项目**，它们像只是因为共用同一套文档模板措辞。纯词面测的是文体不是主题。

### 沉淀提醒（机制 8）

补的是唯一一个**不受任何约束限制**的缺口：闸门保证「写进来的东西干净」，
但**没有任何机制保证「该写的被写了」**。判据刻意保守，三条同时满足才提醒：

- 本会话轮次 ≥ `sedimentMinTurns`（默认 12）；
- 本会话对记忆库的**成功写入次数为 0**；
- 距上次提醒 ≥ 24 轮。

短会话不触发、已经在写的会话永远不触发。它**独立于召回命中**（命中为 0 时才更需要它），
也**不参与注入去重**（去重讲的是「上一轮那份指针还在」，它讲的是「本会话一直没写过」）。

### 归档（`archive.js`）：把历史搬走，不把历史删掉

追加式写法（每批上线往同一篇笔记后面接一段）会让一篇笔记长到 267KB —— 检索时它按整篇
长度归一，就会一直霸占召回位。归档做的事是**物理分层**：

- **只搬追加式章节**：认 `## 第 N 批` / `**第 N 批**` / `### 第 N 批`（中文数字也认）。
  正文里的结论、现状、非批次章节**一律不动**。
- **搬进同目录的 `<笔记>-history.md`**：仍在库里、仍被 `readDocs` 索引、仍能被召回 ——
  所以**没有一步是不可逆的**。超过 90KB 自动续写到 `-history-2.md`，因为写入闸门对单篇
  有 100KB 上限（第一版没做分组，真实库 151KB 的历史直接被自己的闸门拒了）。
- **先备份再动手**：原件写入 `.archive-backup/<时间戳>/`（只读快照，`readDocs` 不递归，
  不进检索）。
- **两段式**：`planArchive` 只读预览 → 面板点「执行」才动库，且每次执行前重新出具计划。
- **碰 `MEMORY.md` 吗？不碰**：索引由另一套守卫管，而且归档是机械派生、不是新事实。

效果（真实库实测）：`project-by-yffto-cicd.md` **267KB → 8KB**，46 个批次搬进 4 份
history 笔记（37 / 90 / 89 / 46KB，全部在闸门上限以内），召回反而变好了 ——
原来这篇自己霸榜，现在命中的是它的 history。

### 「记忆」标签页

客户端 bundle 是**手写的**（`client/client.js`，不需要任何构建工具，只 `require` 平台的
react + primitives），注册到宿主的 `conversation.view` slot，与「对话 / 轨迹」并排。

六个页签：**召回日志**（每轮判定：注入 / 无命中 / 跳过 / 拦截写入 / 沉淀提醒 / 归档，
带展开明细）、**笔记**（可过滤的清单）、**体检**（doctor 的发现，按严重度排序）、
**索引原文**、**归档**（待归档计划 + 一键执行）、**写入审计**（每条放行与拒绝都留痕）。

数据来自插件注册的只读路由 `GET /api/engramory-recall/state`（面板每 3 秒轮询；
体检与归档计划按 30 秒 TTL 缓存，不重算全库）。执行口是另一条必须 `POST` 的路由
（`{ file, confirm: true }`，GET 一律 405）。用 `ctx.inject(['webServer'], …)` 注册 ——
Electron 载体走 `file://` + IPC 时可能没有 webServer，那时召回照常工作，只是没有面板数据。

### 按需检索工具

`engramory_search({ query, limit? })` —— 自动召回没命中时的兜底：模型可以主动搜记忆库
（BM25、只读、离线），拿到「文件名 + 命中片段 + 分数」，再自己 `read` 正文。

## 它不做什么，以及还做不到什么

这一节的初版把**「做不到」和「没做」写成了一样的口气**，读起来像全是能力所限 ——
其实里面好几条只是当时没做。所以拆成三类。

### 一、自愿的约束（能做到，但不做）

- **不写记忆库**：写入只由人和模型判断，走 Engramory 的纪律。一个能自己往库里塞东西的
  记忆插件，等于把用户的笔记变成模型的草稿纸。
- **不删任何东西**：没有自动遗忘、没有自动合并 —— 「合并」意味着原文消失。
- **不建第二份存储**：不建 SQLite、不建向量库、不生成索引文件。markdown 是唯一真相源，
  可读、可 diff、可手改、可跨 Agent 共用。

### 二、真的短板（还做不到）

- **不做语义检索**：没有 embedding、没有向量库。中文用「单字 + 相邻双字」切分，
  同义改写、隐含意图会漏检 —— 目前唯一的桥接是一张 38 条的手工同义表。

### 三、曾经"没做"、现在补上了

- ~~**不自动归档**~~ —— **已实现**。它原来确实写在这一节里，理由也写了（"不可逆"）。
  但 mneme 的 `phaseDemotion` 证明零 LLM 也能做确定性分层，我们只是没做，不是做不到。
  → 做法见上面的「为什么是它」一节末段。
- **不进化（没有自动摘要）** —— 仍然没有，但已经从"不做"降级成"待补"。

### 补短路线图

| 缺口 | 计划 | 状态 |
|---|---|---|
| 追加式日志撑爆单篇 | 物理分层归档，零 LLM | ✅ 已实现 |
| 同义 / 别名鸿沟 | 同义表扩容 + 别名自动利用，零 LLM | ⏳ 下一步 |
| 语义冲突检测 | 走宿主 `ctx.llm`，**默认关闭** | ⏳ |
| 自动摘要 | 走宿主 `ctx.llm`，**默认关闭** | ⏳ |
| 自动合并 | 降级成**只出报告**，不自动改文件 | ⏳ |

后三条为什么默认关闭：为了让「零模型调用」这条基线保持可复现。开启是用户的显式选择，
而不是装完就生效 —— 一个会自己调模型改写你笔记的插件，不该默认打开。
（走 `ctx.llm` 意味着用宿主已经配好的模型，插件自己不配 key、不出网。）

## 配置

改 profile 的 `cordis.patch.yml`（**改完要重启 App 才生效** —— 宿主进程会缓存 ESM 模块）：

```yaml
- insert:
    - id: engramory-recall
      name: dsh-engramory-recall
      config:
        enabled: true            # 总开关
        storePath: ~/memory/engramory
        maxPointers: 4           # 最多注入几条指针
        maxChars: 480            # 注入文本硬上限（字符）
        minScore: 0              # 提高它可以过滤弱命中
        queryChars: 400          # 检索的查询字符预算（超长消息头尾各取一半）
        nudge: true              # 「长期记住」意图提示
        nudgeSediment: true      # 沉淀提醒
        sedimentMinTurns: 12     # 沉淀提醒的轮次门槛
        guardWrites: true        # 写入闸门
        dedupeInjection: true    # 注入去重
        rotationPenalty: 0.5     # 跨轮轮换降权（1 = 关闭）
        rotationHistory: 32      # 轮换记忆长度
        # 下面两个默认关闭：实测无净收益，留着等库里出现半年以上的跨度再复测
        decayHalfLifeDays: 0     # freshness 指数衰减
        recencyWeight: 0         # 时间乘性加权
```

```bash
dsh plugin --profile <profile> add /path/to/dsh-engramory-recall
dsh plugin --profile <profile> remove dsh-engramory-recall
```

> ⚠️ 安装后确认 profile 的 `node_modules/dsh-engramory-recall` 软链**指向真实目录**。

## 集百家之长：一半的机制不是我们想出来的

四家竞品的源码逐个读完（hindsight / 灵枢 dsh-memory / dsh-mnemon / dsh-mneme），
产出要求是「机制 + `文件:行号` + 能否在纯 JS、零依赖、零出网下复刻」。**能搬的搬，
搬不动或搬了没用的当场证伪** —— 证伪的那两条同样有价值，见文末。

| 机制 | 抄自 | 结果 |
|---|---|---|
| 注入去重 | dsh-mnemon `src/host/lifecycle.ts:339-345` | ✅ 落地，但**必须换键**：它比的是整段渲染文本，而我们有跨轮轮换会改变渲染文本 → 照抄就是死代码（真实库探针抓出来的，单测当时还是绿的） |
| 注入预算降级阶梯 | dsh-mneme `src/inject.js:232` | ✅ 落地 —— 装不下就塌缩成只剩文件名，不再静默消失 |
| 跨轮轮换降权 | dsh-mneme `src/inject.js:101` | ✅ 落地，配套细节不可省：候选池要同步扩容 3 倍，否则"降权"只是让位子空着 |
| IDF 选词 cap | hindsight `engine/search/bm25_term_selection.py` | ✅ 落地，但**只能对 `df > 0` 的词排名** —— 按 df 升序取最低的 24 个，留下的全是库里没有的词，实测注入 0 条 |
| fail-closed 闸门 | 灵枢（它只看 `committed` 字段，`ok:true` 不算数） | ✅ 落地 |
| 长查询取样 | 灵枢 issue #108（长查询只有开头段进键） | ✅ 落地 —— 我们犯的是反方向：原来只取尾部 400 字符，把开头的主题句整个丢了 |
| 自动归档 | dsh-mneme `src/dream/sleep.js:411` `phaseDemotion` | ✅ 落地，但**换了实现**：它截断 + 存 `_full_content`，我们整段搬家、不截断 |
| 时间衰减 | 灵枢 `rust/src/freshness.rs` | ❌ **实测证伪** —— 六档半衰期扫描，recall 恒定、top-1 只有一档 +1（噪声级）。灵枢能用是因为它的 `protected_floor` 依赖人工 `importance` 字段，Engramory 笔记没这个字段 |
| 时间乘性加权 | hindsight `engine/search/reranking.py:35-37` | ❌ **实测证伪** —— 五档扫描净收益为零，`w ≥ 0.1` 起还要拿对照组去换 |
| 同义表扩容 / 别名自动利用 | 灵枢的语义归一化 | ⏳ 待补（零 LLM 那条路） |

> **搬机制最容易犯的错**：把机制搬过来，却没搬它依赖的不变量。mnemon 没有跨轮轮换，
> 所以它的「渲染文本不变」是真的不变；我们加上轮换之后，同一个写法就成了永远不触发的死代码。
> **抄之前先问：它凭什么成立？那个前提我这儿也有吗？**
